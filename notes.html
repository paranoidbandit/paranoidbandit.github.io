Wireshark & Packet Analysis

Passive recon, credential sniffing on a pivoted segment, and the go-to tool for ICS/OT protocol analysis before touching a live PLC.

Display Filters — IP / Host

ip.addr == 10.10.50.1                          # either src or dst
ip.src == 10.10.50.1
ip.dst == 10.10.50.1
ip.addr >= 10.10.50.1 and ip.addr <= 10.10.50.100   # range
ip.addr == 10.10.50.1 and ip.addr == 10.10.50.100    # both hosts in convo
!(ip.addr == 10.10.50.1)                        # exclude a host

Display Filters — Port / Protocol

tcp.port == 445
udp.port == 53
http or dns or ftp
tcp.flags.syn == 1 and tcp.flags.ack == 0        # SYN scans / new connections
tcp contains "password"                          # raw string search across the payload
frame contains "flag{"                            # CTF-style flag hunting

Finding Cleartext Credentials

http.request.method == "POST"                    # then follow HTTP stream, check for login fields
ftp.request.command == "USER" or ftp.request.command == "PASS"
telnet
pop.request.command == "USER" or pop.request.command == "PASS"
snmp.community                                    # SNMP community strings in cleartext

Follow Streams & Extract Files

  • Right-click a packet → Follow → TCP Stream (or HTTP/TLS Stream) to read a full conversation
  • File → Export Objects → HTTP/SMB/FTP — pull transferred files straight out of a capture
  • Statistics → Conversations — quick overview of who talked to whom, and how much
  • Statistics → Protocol Hierarchy — spot unexpected protocols buried in a large pcap
  • Have a TLS keylog file (SSLKEYLOGFILE)? Edit → Preferences → TLS → (Pre)-Master-Secret log filename to decrypt HTTPS in the capture

ICS / Industrial Protocol Filters

modbus                                            # Modbus TCP (port 502)
s7comm                                            # Siemens S7 (port 102)
dnp3                                              # DNP3 (port 20000)
cip                                               # EtherNet/IP (44818)
profinet_io                                       # Profinet

tshark (CLI / headless)

# Live capture, filtered
tshark -i eth0 -f "tcp port 445"

# Read a pcap with a display filter, print specific fields
tshark -r capture.pcap -Y "http.request" -T fields -e ip.src -e http.host -e http.request.uri

# Pull ICS traffic out of a large capture for offline review
tshark -r capture.pcap -Y "modbus || s7comm" -w ics_only.pcap

# Dump raw ASCII payload (grep-able for creds/flags)
tshark -r capture.pcap -T fields -e data.text 2>/dev/null | grep -i pass

Kerberoasting AD

OSCP mindset: Kerberoasting is an authenticated attack against user accounts that have Service Principal Names (SPNs). Enumerate SPNs, identify worthwhile service accounts, request TGS tickets, then perform offline password auditing. A normal domain account is typically enough to request a service ticket; the value comes from whether the service account password is weak and whether that account has useful privileges.

What to Look For

  • SPN on a user account — this makes the account a Kerberoasting candidate.
  • Service accounts such as SQL, IIS, backup, monitoring, or application accounts.
  • Password age / password hygiene — old or human-managed service-account passwords can be especially interesting.
  • Privilege of the target account — a cracked service account is more valuable if it has administrative rights or useful group membership.
  • Delegation relationships — after obtaining a service account, re-check delegation and BloodHound paths.

No longer required on the current OSCP exam, but still useful knowledge. Steps for classic 32-bit Windows stack BOF.

Workflow

  1. Spike / Fuzz — find the vulnerable command
  2. Crash — confirm with cyclic pattern of A's

Avoid Detection Tips

  • Compress + encrypt before sending: zip -P pass loot.zip /etc/shadow or 7z
  • Use port 80/443/53 for exfil — less likely to be filtered

Exam Tips & Workflow

Time Management (24h)

  • Hour 0–1: full nmap on all targets, kick off enum scripts in parallel
  • Spend max ~3-4 hours on initial foothold per box. Stuck → rotate.
  • Sleep 4–6 hours. Tired brain = stuck brain.
  • Last 2 hours: stop hacking, start screenshotting if you haven't already

Note-Taking Discipline

  • Screenshot every step that contributes to compromise
  • Show the local.txt / proof.txt + ipconfig/ifconfig + whoami in the same screenshot
  • Record exact commands — copy-paste, don't retype
  • Tools: CherryTree, Obsidian, Joplin, Sysreptor

When You're Stuck

  • Re-read all enum output. The answer is usually already there.
  • Run a different scanner (gobuster → ffuf, linpeas → linenum)
  • Look for unusual ports / banners / version numbers
  • Search exact version strings: searchsploit X, github, blog write-ups of similar CVEs
  • Check default creds (admin:admin, tomcat:tomcat, etc.)
  • Walk away for 10 minutes. Eat something. Hydrate.

Report

  • Use the official OffSec template or Sysreptor
  • Each finding: description, affected target, steps to reproduce, evidence (screenshots), remediation
  • Submit within 24h of exam end. Don't wait.

Common Snags

Reverse shell won't catch? Try a different port (80/443/53), URL-encode the payload, or use a different shell type (powershell vs cmd vs nc.exe).
Nothing runs on the target? AppLocker / AV. Try built-in LOLBAS, PowerShell -EncodedCommand, iex from memory, or AMSI bypass.
Banned in exam: Metasploit (except ONE use total — meterpreter, multi/handler, post modules), commercial tools, automated exploit frameworks (sqlmap allowed). Read OffSec's policy doc the week before.

Mindset

Try Harder isn't a slogan — it's an instruction. When you're tired, sloppy, and convinced this box is unhackable: that's exactly when re-checking your enumeration finds the foothold. Trust the process.
